Preface


CTF competitions are rarely just about running an automated tool or running a dictionary attack. The most memorable challenges are puzzles that force you to look closely at the foundational data formats—the byte-level structures of ZIP archives, the IHDR chunk signatures of PNG files, the bitplanes of uncompressed RGB channels, and the exact packet framing of raw network captures.


During V1T CTF 2025, our team encountered a series of forensic, steganographic, and cryptographic challenges that demanded creative reverse-engineering:

This writeup documents the step-by-step methodology, investigative thought processes, and custom scripts developed to solve all four challenges.


Challenge 1: 67 (Steganography & AES Bitplane Carving)


The challenge begins with a single archive: challenge.zip.


1. Initial Metadata Reconnaissance


Before jumping into unzipping, checking the archive's metadata using exiftool reveals critical contextual hints:



The comment in the ZIP metadata immediately catches our eye:


"u AlrEady know the ruleS | (36-4) + (36-4) = 67 - 3."

Challenge 4: Tryna crack? (ZipCrypto KPA & IHDR Height Repair)


The challenge file is challenge.zip.


1. Archive Inspection: The ZipCrypto Vulnerability


Examining the archive structure using zipinfo:



Two critical details stand out:


  1. BX stor: The compression method is stored (0.0% compression). The compressed ciphertext corresponds byte-for-byte to the plaintext.
  2. The encryption scheme is legacy ZipCrypto (PKZIP stream cipher).


Because PNG files have a standardized 8-byte file signature (89 50 4E 47 0D 0A 1A 0A) followed immediately by the 4-byte chunk type IHDR (49 48 44 52), we have at least 12 contiguous bytes of known plaintext. This makes the archive entirely vulnerable to a Known-Plaintext Attack (KPA).


2. Recovering Encryption Keys via `bkcrack`


We create a 9-byte plaintext probe containing the PNG header and the start of IHDR, then launch bkcrack:



Within minutes, bkcrack reconstructs the internal cipher keys (4672d551 bcb3adcb c76d52c5) and outputs the decrypted PNG: quackquackquack.png.

Technical Summary & Core Takeaways


Solving these four challenges highlights several core principles of practical security analysis:


  1. Metadata Is Never Incidental: In every single challenge (67, Fuck Da Binary, Thirsty Sick, and Tryna crack?), critical cryptographic parameters and algorithmic directions were embedded directly into ZIP comments and Exif tags.
  2. Recognizing Encryption Bounds: ZipCrypto's internal state can be mathematically collapsed with as few as 9 bytes of known plaintext when compression is disabled. Modern security architectures should always mandate AES-256 (WinZip AE-2) or authenticated encryption.
  3. Stream Deinterleaving & Modular Arithmetic: Network forensics often requires looking beyond standard protocol parsers. When files are interleaved in fixed byte blocks, modular index filtering (i % (BLOCK_SIZE * 2)) provides clean algorithmic separation.
  4. Header Integrity vs. Stream Content: Image viewers blindly trust declared chunk headers. When analyzing suspicious PNGs or JPEGs, inspecting raw scanline volume against declared dimensions frequently exposes hidden data.
